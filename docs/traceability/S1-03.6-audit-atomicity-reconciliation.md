## Scope and non-claims

S1-03.6 reconciles the audit-atomicity acceptance criterion originally
delivered in merged PR #6 (`9563ef2a308aa611338c8d20e567214e5b67995c`) with
the current protected Memory Core ledger through migrations `0013`--`0015`.
It adds no second writer, migration, Goal or Action runtime, external effect,
approval, budget, resource claim, fence, sandbox, learning promotion, or
recognition claim.

ADR-018 and Directive v4.0 retain the Memory Core as a protected subsystem,
not the product boundary. The sole implemented protected-state writer remains
`memory_gate.commit_memory_cycle`; its transaction must either commit the
complete Memory transition and audit evidence or commit none of them. Audit or
tool success is not a Goal or external-effect success claim.

## Verification boundary

The injected trigger is test-only administrative fault injection, not a
runtime bypass: it validates that an audit failure fails closed. The test
neither grants table DML to a Runtime role nor alters the Gate implementation.
The identity sequence may consume a value on rollback; no protected audit row,
chain head, receipt, or domain transition is thereby committed.

PostgreSQL 18 migration validation remains required in CI for a fresh and
forward-upgrade schema proof. A local skip caused only by an unavailable
`MIGRATION_ADMIN_DSN` is not release evidence.
