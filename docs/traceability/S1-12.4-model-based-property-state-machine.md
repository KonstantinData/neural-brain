# S1-12.4 model-based property state-machine evidence

## Scope

- Task: `S1-12.4 — Implement model-based and property-based state-machine tests`
- Current implementation boundary: MS-1 Memory Core only
- Generated trace budget: exactly 100,000 Hypothesis sequence examples
- Generated model-operation budget: exactly 600,000 sequence steps
- Durable test: `tests/property/test_s1_12_4_memory_state_machine.py`

This evidence exercises the current synchronous `MemoryService` and the
existing deterministic atomic repository boundary. It does not implement,
simulate, authorize, or claim a Goal, Action, Executor, tool, external-effect,
or dispatch runtime.

## Model and generated transitions

Every generated trace owns one persistent model and repository state across six
operations. Its generated sequence starts with commit, injected rollback, and
retry so later generated operations always execute after real state changes.
Hypothesis then generates three additional operations over a 63-bit seed space.
This produces exactly 100,000 multi-step traces and 600,000 modeled sequence
steps, rather than counting isolated parameter cases as traces.

| Step | Implementation or contract oracle | Expected terminal outcome |
| --- | --- | --- |
| `advance` | `MemoryService` plus deterministic repository | One monotone version and one audit receipt commit |
| `exact_replay` | Repository replay receipt | Original result, no new version or audit receipt |
| `conflicting_replay` | Repository replay-key guard | Denied, no protected-state change |
| `stale_write` | Working-memory compare-and-set | Denied, no protected-state change |
| `rollback_write` | Injected pre-commit failure | Attempt reaches absorbing `rolled_back`; protected state, replay receipts, audit, and failpoint return to the prior snapshot |
| `retry_rolled_back` | Persistent model pending request | Same request commits once, or is denied if an intervening commit made its expected version stale |
| `cross_scope_read` | Authenticated Runtime Context | Foreign Tenant/Area reads are unavailable and reveal no record |
| `incomplete_authority` | Current Security Floor | Missing Project/Session authority is denied before repository mutation |
| `dreaming_denied` | Current `MemoryService` | Dreaming remains unavailable and quiescent at MS-1 |
| `reconciliation_required` | Normative Memory Lifecycle contract | Unknown outcomes require reconciliation; no reconciliation runtime is claimed |
| `dispatch_na` | Memory Stage and system-boundary contracts | Dispatch is absent, N/A, and cannot mutate Memory Core state |

The test model records each request attempt in one of the explicit absorbing
terminal states `committed`, `replayed`, `denied`, `rolled_back`, or
`not_applicable`. Later operations must preserve the complete prior terminal
history while acting on the persistent committed version, last replay receipt,
and optional pending retry.

The model oracle checks after every sequence step that observation and
checkpoint counts equal committed versions, exactly one scoped working-memory
record carries the monotone version, audit IDs are unique and commit-count
matched, replay receipts are commit-count matched, checkpoint versions are
gap-free, the failpoint is cleared after rollback, and every persisted record
retains the authenticated Tenant, Area, Project, and Session scope. Quiescence
snapshots include repository records, audit IDs, replay receipts, the armed
failpoint, and the model's pending-retry reference.

## Invariant coverage

| Required evidence | Generated proof |
| --- | --- |
| Terminality | Each request attempt enters one explicit absorbing outcome. Follow-up operations preserve all prior outcomes while continuing against the same persistent model. |
| Memory quiescence | Replay, stale/conflicting input, cross-scope reads, incomplete authority, Dreaming denial, reconciliation-only checks, and dispatch N/A preserve the complete repository/replay/failpoint snapshot and pending model state. |
| Authenticated authority and scope | The service admits complete trusted Runtime Context only and rejects missing or foreign scope without accepting scope from request payloads. This is the currently implemented Security Floor boundary, not a claim that later authority-grant integration is complete. |
| Ledger and replay atomicity | Successful versions, checkpoints, and audit receipts advance together; exact replay is idempotent; changed replay keys and stale versions fail without partial state. |
| Reconciliation | The normative contract remains `ready_default = false` and forbids blind retry after an unknown commit outcome. No reconciliation runtime is represented as implemented. |
| Dispatch | Current memory operations contain no dispatch surface; Cognitive Plane external effects are denied. This is negative N/A evidence only. |
