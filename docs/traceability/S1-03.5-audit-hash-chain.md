# S1-03.5: MS-1 Canonical Audit Hash Chain

- Status: implemented MS-1 foundation control
- Task: S1-03.5
- Governing decisions: ADR-003, ADR-015 (retained Memory Core authority),
  ADR-018, ADR-019, Architecture Directive v4.0
- Delivery stage: NB-0 / MS-1 foundation only

## Scope and non-claims

This task hardens the retained, protected Memory Core audit ledger. It does not
introduce a Goal or Action runtime, approval, budget, resource claim, fence,
external effect, candidate lifecycle, retrieval, promotion, deletion, or a
second protected-state writer. `memory_gate.commit_memory_cycle` remains the
sole implemented Memory Transition Gate writer; audit event insertion stays in
that atomic transaction.

## Integrity control

Migration `0013_memory_audit_hash_chain.sql` adds SHA-256 chain fields to each
new `memory_audit.events` row. The canonical input includes the full immutable
scope, identity, event, evidence, UTC instant, scoped audit sequence, and the
previous hash. A per-Tenant/Area `chain_heads` anchor binds count, last
sequence, and terminal hash, so changing an event, deleting a terminal event,
or changing the audit order fails verification. `memory_gate.verify_memory_audit_chain`
is a scoped, authenticated read Gate and never exposes table DML.

The install verifier explicitly catalogs that read Gate for only
`neural_brain_gate` and `neural_brain_reader`. The canonical-hash and trigger
helper functions remain owner-only internal routines; `PUBLIC` has no execute
right on any new `memory_audit` function.

Existing audit rows are deliberately not assigned invented hash values. The
migration fails closed until an independently authorized, audited reconciliation
can establish a truthful historical anchor. This is an upgrade blocker, not a
claim that a reconciliation runtime exists.

## Automated evidence

- `tests/database/test_stage1_memory_kernel.py::test_audit_hash_chain_detects_changed_removed_and_reordered_events`
  proves verification succeeds for ordinary gate-written events and fails for
  administrative tampering with payload, terminal deletion, and sequence order.
- `tests/traceability/test_s1_03_5_audit_hash_chain.py` protects the bounded
  scope, canonical SHA-256 chain, gate-only verifier, fail-closed upgrade, and
  no-early-runtime claims.
- `tests/migrations/test_migration_validation.py` proves clean installation and
  forward-upgrade schema equivalence when `MIGRATION_ADMIN_DSN` is available.

Local PostgreSQL evidence requires `MIGRATION_ADMIN_DSN`; a skip is not release
evidence. Required CI runs the disposable PostgreSQL 18 suite.
