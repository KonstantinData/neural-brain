# S1-03.4: MS-1 Transition History and Terminal Receipt Evidence

- Status: implemented MS-1 foundation control
- Task: S1-03.4
- Governing decisions: ADR-015 (retained Memory Core authority), ADR-018,
  ADR-019, Architecture Directive v4.0
- Delivery stage: NB-0 / MS-1 foundation only

## Scope and non-claims

ADR-018 and Architecture Directive v4.0 define the full protected cognitive
system.  This task only strengthens the retained Memory Core boundary.  It
does not introduce a Goal or Action runtime, a general lifecycle state machine,
candidate promotion, quarantine, deletion, retrieval, external effects, or a
second protected-state writer.

`memory_gate.commit_memory_cycle` remains the sole MS-1 writer.  Its completed
`memory_core.transition_receipts` row is the terminal representation of that
idempotent gate operation: replay returns its recorded result; any attempted
update or deletion is rejected.  A correction must therefore be a new,
authorized transition with its own audit evidence, not a rewrite of history.

## Database invariant

Migration `0012_memory_transition_history_immutability.sql` installs one
fail-closed trigger function on the historical MS-1 projections:

| Protected history | Why it is immutable | Database enforcement |
| --- | --- | --- |
| `memory_core.working_context_versions` | Versioned prior working-memory values are transition history. | `working_context_versions_are_immutable` rejects `UPDATE` and `DELETE`. |
| `memory_core.checkpoints` | A checkpoint is a recovery evidence snapshot, not mutable working state. | `checkpoints_are_immutable` rejects `UPDATE` and `DELETE`. |
| `memory_core.transition_receipts` | A committed receipt is a terminal, idempotent Memory Transition Gate outcome. | `transition_receipts_are_immutable` rejects `UPDATE` and `DELETE`; a receipt cannot transition out of its committed terminal outcome. |

The trigger raises SQLSTATE `55000`.  It is independent of runtime DML
privilege revocation and RLS, so a database table-DML interface cannot silently
rewrite these historical rows.  The control does not turn a tool result into
goal success and does not authorize a new effect or memory lifecycle operation.

  proves a live PostgreSQL interface rejects modification and deletion of all

  prevents accidental removal of the bounded scope, all three trigger guards,
